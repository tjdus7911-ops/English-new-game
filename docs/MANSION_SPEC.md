# 수상한 저택의 상속자 — 영어 학습 리모델링 게임 통합 기획서 v1.2

> v1.0(리모델링 MVP) → v1.1(화면 방향 정책) → **v1.2(연결된 저택 맵 · 캐릭터 작업 애니메이션 · 스토리/영어 추리)** 를 하나로 합친 문서입니다.
> 구현 위치는 각 항목 끝 `→ 코드` 로 표시합니다. 미구현은 **[미구현]**, 임시 에셋은 **[임시]** 로 구분합니다.

## 0. 핵심 루프

영어 학습(세로) → 스테이지 최초 통과 ★1 → 저택 맵(가로)에서 미션 확정(★ 차감) → 관리인 이동·작업 애니메이션 → 오브젝트 변경 → 스토리 이벤트 → 영어 추리 퀴즈(★ 없음) → 단서 획득 → 다음 미션

필수 정책과 구현:
1. **저택 → 학습 진입 시 세로 전환**, 2. **학습 종료 → 저택 복귀 시 가로 전환**: 라우트가 바뀔 때마다 `lockOrientation()` 호출. → `src/app/orientation.tsx`
3. **상태 보존**: 단일 스토어(IndexedDB) + 회전 안내는 화면을 언마운트하지 않는 오버레이 → 학습 진행(문항 위치)·별·리모델링 유지. E2E로 검증.
4. **Android 네이티브**: Capacitor + `@capacitor/screen-orientation` 으로 경로별 `lock({ orientation })`. Activity 는 `configChanges` 에 orientation/screenSize 포함(재생성 방지). → `capacitor.config.ts`, `android/`
5. **모바일 웹 대체 UI**: `screen.orientation.lock` 은 대부분 전체 화면에서만 허용되고 iOS Safari 는 미지원 → 실패 시 "기기를 가로/세로로 돌려 주세요" 오버레이 + `전체 화면으로 자동 회전`(지원 브라우저) + `이대로 계속하기`(비율 유지 표시).
6. **가로 화면비 대응**: 맵은 카메라가 화면 크기에 맞춰 기본 배율을 다시 계산(ResizeObserver), HUD 는 화면 가장자리 + `env(safe-area-inset-*)` 고정.
7. **세로 해상도 대응**: 기존 모바일 컬럼 레이아웃(최대 560px) 유지, 데스크톱에서는 가운데 정렬.
8. 와이어프레임·기능정의서: 아래 4·5장에 방향 열을 추가해 반영. Figma `M1~M4` 페이지.

## 2. 저택 맵 구조 (v1.2 최우선 변경)

- 폐기: 층별 인형의 집 전체 화면, 방 선택 → 별도 방 화면 이동 방식.
- 채택: **정원(좌) · 거실/현관(중앙) · 주방(상단) · 복도/계단(우측)** 이 하나로 이어진 2D 아이소메트릭 월드(3900×1900 px, 타일 120×60).
- 방을 눌러도 화면 전환 없음 → 카메라만 이동. 잠긴 공간은 어둡게 + 🔒 표지 + "CH.0X 준비 중" 안내.
- 카메라: 드래그 이동, 핀치 줌, 휠 줌, 이동 범위 제한(월드 밖 노출 금지), 미션 선택 시 대상 포커스, 스토리 이벤트 시 오브젝트 포커스, 완료 후 기본 위치 복귀. 탭/드래그 구분(8px).
- 레이어: `background(지면)` → `floor` → `walls·built-ins(창문·문·계단)` → **`objects`(가구·장식·캐릭터·칸막이벽을 아이소 깊이 gx+gy 로 정렬)** → `fx` → `hotspots`. 캐릭터가 가구 앞뒤를 자연스럽게 지나가도록 v1.0 의 고정 레이어(가구/장식/캐릭터)를 하나의 깊이 정렬 레이어로 통합.
- 각 공간·오브젝트는 독립 상태: 바닥 청소는 거실 바닥 레이어만, 소파 교체는 소파 슬롯만 바뀌고 다른 공간·가구는 유지.
→ 코드: `src/game/mansion/{iso,mapData,MansionWorld,Camera,Sprites}.ts(x)`

## 3. 기술 선택

Phaser 를 검토했으나 MVP 규모(오브젝트 수십 개)에서는 **React + DOM 아이소메트릭 렌더러**로 결정: 기존 앵커 기반 에셋 파이프라인·접근성(버튼/스크린리더)·E2E(data-testid) 유지, 깊이 정렬·rAF 카메라/이동 트윈·CSS steps 스프라이트로 요구사항 충족. 렌더러는 `MansionWorld` 하나로 분리되어 오브젝트 수가 크게 늘면 Phaser 씬으로 교체 가능.

## 7. 스토리 — 「수상한 저택의 상속자」

핵심 질문: **전 주인은 왜 하필 하루에게 이 저택을 남겼을까?** (미스터리 + 코미디 + 따뜻한 일상, 무섭지 않게)

캐릭터(전부 자체 창작, 같은 SVG 원본에서 모든 프레임 생성 → 외형·비율·색 일관): `content/story/characters.ts`
- **하루**(주인공): 갈색 단발·겨자색 후드. 현실적·호기심·엉뚱. 영어 초보 → 단서를 풀며 성장.
- **오브리**(관리인): 흰 옆머리·둥근 안경·청록 카디건·빨간 나비넥타이. 친절하지만 전 주인 얘기엔 "자자!"로 말 돌림. 작업 담당.
- **호두**(고양이): 주황·흰색, 파란 방울 목걸이. 숨겨진 물건을 찾아냄.

## 8. 저장 데이터 (v4)

`AppState.mansion`: `stages`, `renovations`, `ledger`(earn/spend + idempotencyKey), `processedAttempts`, `story { completedEvents, currentEventId, clues, quizzes }`. 별 잔액 = earn 합 − spend 합. 기존 학습 데이터(answers·wrongNotes·reviews·log)는 그대로이며 스테이지 결과가 함께 기록된다. 서버 없음 → 기기 변경 시 복구 불가(설정 화면에 안내).

## 9. 에셋 구조

```
public/assets/game/
  manifest.json                 키 → {w, h, anchor} (기준점 = 하단 중앙/중심)
  mansion/                      ← 이번 개편 (자체 제작 SVG → WebP, scripts/mansion-art)
    char-{haru,aubrey,hodu}.webp      스프라이트 시트 (행=동작, 열=프레임)   + src/game/mansion/sprites.json
    portrait-{haru,aubrey,hodu}.webp  표정 시트 (열=표정)
    debris-*, old-{sofa,armchair,painting}, armchair-*, table-*, letter-*, key-brass, photo-old, wall-pattern, sign-locked, stairs-rope
    wall-old, wall-damask, floor-old, floor-parquet, kitchen-tile-old, stone, grass   (384→256 타일 텍스처)
  furniture/ house/ garden/      ← 기존 그림체 에셋 재사용 (소파·조명·러그·장식장·벽지/바닥·정원)
art/mansion-svg/*.svg            원본 SVG (Figma 에 벡터로 가져갈 수 있음)
art/sheets/mansion-*.png         Figma AI 시트 [다운로드 대기]
```

규칙: 가구 1점 = 파일 1개 = 매니페스트 키 1개. 미션 variant 는 `assetKey` 로만 참조 → 에셋 교체 시 코드 수정 없이 파일·매니페스트만 바꾸면 된다. 전체 배경 이미지 교체 방식 금지(바닥·벽은 텍스처 레이어, 가구는 슬롯 스프라이트).
